# Сценарии использования

Для каждого сценария альтернативные ветви являются уточнениями аналитической модели. Результаты выполнения системой не заявляются как проверенные.

## UC-01. Авторизация и регистрация

**Основной участник:** Посетитель  
**Требования:** FR-01, FR-02  
**Предусловия:** Пользователь не авторизован.

### Основной поток

1. Пользователь выбирает вход или регистрацию.
2. Система предлагает доступные способы входа.
3. Пользователь вводит необходимые данные и подтверждает владение контактом, если это требуется выбранным способом.
4. Система проверяет данные и создаёт сессию; при регистрации создаёт учётную запись.

### Альтернативы и ошибки

- Некорректные данные: система сообщает об ошибке без раскрытия существования чужого аккаунта.
- Недействительный код: доступ не предоставляется, доступен повторный запрос с ограничением частоты.
- Внешний провайдер недоступен: предложить другой способ входа.

**Постусловия:** Пользователь авторизован; ошибка входа не создаёт сессию.

## UC-02. Оформление отправления

**Основной участник:** Авторизованный пользователь  
**Требования:** FR-03, FR-04, FR-05  
**Предусловия:** Пользователь авторизован.

### Основной поток

1. Пользователь выбирает тип отправления.
2. Вводит адреса, параметры отправления и данные сторон.
3. Система проверяет поля и получает доступные тарифы.
4. Пользователь выбирает тариф и подтверждает оформление.
5. Система сохраняет заказ с уникальным идентификатором и статусом оплаты.

### Альтернативы и ошибки

- Некорректный адрес или параметры: показать ошибки, сохранить введённые данные.
- Нет подходящего тарифа: не создавать оплачиваемый заказ, предложить изменить параметры.
- Повторное подтверждение: не создавать дубликат.

**Постусловия:** Создан один заказ. Его оформление не означает, что посылка уже передана перевозчику.

## UC-03. Отслеживание отправления

**Основной участник:** Посетитель  
**Требования:** FR-06  
**Предусловия:** Известен трек-номер; вход в аккаунт не требуется.

### Основной поток

1. Пользователь вводит трек-номер.
2. Система проверяет формат и запрашивает статус.
3. Отображает статус и доступную историю движения.

### Альтернативы и ошибки

- Неверный формат: запрос не отправляется до исправления.
- Отправление не найдено: показать сообщение, не подменять его статусом ошибки доставки.
- Источник статусов недоступен: сообщить о временной недоступности; кешированные данные показывать с временем обновления.

**Постусловия:** Показан результат поиска без раскрытия избыточных персональных данных.

## UC-04. Оплата услуги

**Основной участник:** Авторизованный пользователь  
**Требования:** FR-07, FR-08  
**Предусловия:** Есть собственный заказ с суммой к оплате.

### Основной поток

1. Пользователь открывает заказ и выбирает способ оплаты.
2. Система создаёт платёжную операцию и направляет пользователя к провайдеру.
3. Пользователь выполняет оплату у провайдера.
4. Система получает подтверждённый результат от провайдера и обновляет платёжный статус.

### Альтернативы и ошибки

- Пользователь отменил оплату: заказ не становится оплаченным.
- Результат пока неизвестен: отобразить ожидание подтверждения.
- Повторное уведомление провайдера: не проводить повторное зачисление.
- Не совпали заказ, валюта или сумма: не подтверждать успешную оплату, зафиксировать ошибку.

**Постусловия:** Статус оплаты соответствует подтверждённой операции. Возврат пользователя на сайт сам по себе не подтверждает платёж.

## UC-05. Поиск отделения

**Основной участник:** Посетитель  
**Требования:** FR-09  
**Предусловия:** Доступна страница поиска.

### Основной поток

1. Пользователь вводит адрес или разрешает определение местоположения.
2. Система показывает подходящие отделения.
3. Пользователь открывает адрес, график и доступные услуги отделения.

### Альтернативы и ошибки

- Геолокация отклонена: остаётся поиск по введённому адресу.
- Результатов нет: предложить изменить область поиска.
- Карта недоступна: сохранить текстовый список, если источник отделений доступен.

**Постусловия:** Пользователь может выбрать отделение без обязательного доступа к геолокации.

## UC-06. Вызов курьера

**Основной участник:** Авторизованный пользователь  
**Требования:** FR-10  
**Предусловия:** Пользователь авторизован.

### Основной поток

1. Пользователь указывает адрес, тип услуги и параметры отправления.
2. Система проверяет доступность курьера и показывает интервалы и стоимость.
3. Пользователь подтверждает выбранный вариант.
4. Система сохраняет заявку и показывает её идентификатор и статус.

### Альтернативы и ошибки

- Адрес вне зоны обслуживания: заявка не подтверждается.
- Интервал занят: предложить актуальные интервалы.
- Ошибка внешнего сервиса: не сообщать о подтверждённом визите без подтверждения.

**Постусловия:** Заявка зарегистрирована либо пользователь получил определённый результат отказа.

## UC-07. Управление личным кабинетом

**Основной участник:** Авторизованный пользователь  
**Требования:** FR-11, FR-12  
**Предусловия:** Пользователь авторизован.

### Основной поток

1. Пользователь открывает профиль или историю заказов.
2. Система показывает только доступные ему данные.
3. Пользователь меняет разрешённые поля.
4. Система проверяет поля и подтверждение чувствительных изменений, затем сохраняет результат.

### Альтернативы и ошибки

- Недостаточно прав: отказ в доступе.
- Не пройдено подтверждение: защищаемые поля не меняются.
- Сессия истекла: требуется повторный вход.

**Постусловия:** Изменены только разрешённые данные; чужие заказы недоступны.

## UC-08. Обращение в поддержку

**Основной участник:** Посетитель  
**Требования:** FR-13  
**Предусловия:** Доступен раздел помощи.

### Основной поток

1. Пользователь открывает помощь.
2. Система предлагает FAQ и доступный канал обращения.
3. Пользователь задаёт вопрос и оставляет необходимые для ответа сведения.
4. Система подтверждает приём обращения идентификатором, если обращение создано.

### Альтернативы и ошибки

- Чат недоступен: предложить форму обращения.
- Не заполнены обязательные поля: пояснить ошибки.
- Сбой сохранения: не выдавать несуществующий номер обращения.

**Постусловия:** Показан ответ FAQ либо зарегистрировано обращение. Общая помощь доступна без входа.

## UC-09. Участие в благотворительной программе

**Основной участник:** Авторизованный пользователь  
**Требования:** FR-14  
**Предусловия:** Пользователь авторизован; программа доступна.

### Основной поток

1. Пользователь выбирает программу.
2. Система показывает получателя, условия и способ участия.
3. Пользователь подтверждает выбранное действие.
4. Если требуется платёж, система использует сценарий UC-04 и показывает подтверждённый результат.

### Альтернативы и ошибки

- Программа завершена: участие недоступно.
- Оплата отклонена или не подтверждена: не показывать успешное пожертвование.
- Внешняя программа: явно обозначить переход на сторонний ресурс.

**Постусловия:** Результат соответствует подтверждённому действию; перечисление денег не имитируется.

## UC-10. Управление заказами

**Основной участник:** Администратор  
**Требования:** FR-15, FR-16  
**Предусловия:** Администратор авторизован и имеет нужное разрешение.

### Основной поток

1. Администратор находит заказ.
2. Система показывает разрешённые сведения и действия.
3. Администратор выбирает изменение и указывает причину, когда она требуется.
4. Система проверяет допустимость перехода, сохраняет результат и запись аудита.

### Альтернативы и ошибки

- Недостаточно прав: операция отклоняется.
- Недопустимый переход статуса: данные не изменяются.
- Заказ уже изменён другим действием: запросить актуальные данные.

**Постусловия:** Допустимое изменение сохранено и зарегистрировано; финансовый статус нельзя произвольно объявить успешным.
